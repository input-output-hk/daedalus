## Disposable profile and launch specification

The prepared private paths are in `.git/analytics-completion-review/prepared-profile.json`.
The helper `.git/analytics-completion-review/prepare-wallet.cjs` records the exact
Nix source outputs, copies read-only dependencies and creates a new empty profile.
It refuses to replace an existing prepared profile and starts nothing. The matching
Nix-generated config keeps required arguments, uses a unique node pipe, disables
the updater and omits optional Mithril. It is a consent-only empty-wallet test;
normal Preprod network connectivity/disk space are still needed.

Do not install this build over Mainnet, Pre-Prod or Preview. Use an unpackaged
Electron checkout. Create a new directory beneath
`%LOCALAPPDATA%\DaedalusAriadneReview\<random-review-id>`; record that exact path
privately and reuse it only for the restart steps. Never copy existing app data,
settings, TLS keys, chain databases or wallet databases into it. Keep the installed
wallet closed during this test to avoid confusing windows or ports.

Before importing `dist/main/index.js`, a review-only Electron entry script must
create and set these paths (changing the backend path alone does not isolate
`electron-store`):

```javascript
// Run as Electron's entry, before importing any Daedalus module.
// reviewRoot is the newly allocated absolute disposable directory.
const { app } = require('electron');
const fs = require('node:fs');
const path = require('node:path');
app.setName('Daedalus Ariadne Review');
for (const [name, directory] of Object.entries({
  userData: 'electron',
  sessionData: 'chromium',
  logs: 'electron-logs',
  crashDumps: 'crashes',
})) {
  const target = path.join(reviewRoot, directory);
  fs.mkdirSync(target, { recursive: true });
  app.setPath(name, target);
}
// Finally require the absolute path to this checkout's dist/main/index.js.
```

The prepared `entry.cjs` implements this specification before loading the main
bundle. Its absolute path and the isolated JSON are recorded privately. Do not replace it with a generic `--user-data-dir` assumption. Electron's
[path API](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path)
requires session paths to be set before readiness. Its
[native module guide](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)
explains why Node-installed binaries alone do not prove Electron compatibility.

## Synthetic event probe

No wallet creation/restoration or transaction is necessary. From DevTools attached
to the wallet's own main frame, define this synthetic probe. It sends no wallet
data and **does not grant consent**; consent remains an explicit UI action.

```javascript
window.ariadneReviewProbe = async () => {
  const view = await window.ipcRenderer.invoke('ARIADNE_ANALYTICS_CONSENT_V1', {
    get: true,
  });
  return window.ipcRenderer.invoke('ARIADNE_ANALYTICS_EVENT_V1', {
    type: 'page_view',
    action: 'Support',
    ts: new Date().toISOString(),
    generation: view.generation,
    uses_legacy_wallet: false,
    uses_hardware_wallet: false,
  });
};
await window.ariadneReviewProbe();
```

`true` means admitted to the in-memory client queue, not stored at Ariadne.
The probe exercises the real main-frame IPC, consent owner and HTTP path, but
deliberately injects synthetic flags instead of reading wallet metadata. It does
not replace testing ordinary renderer navigation after the empty wallet list loads.
No dashboard response should contain an installation UUID.

## Manual acceptance checklist (not yet executed)

Record the dashboard baseline for **Preprod** and today's UTC date. Counts may
also include automatic approved navigation events; use changes, not an assumed
exact total. Do not send synthetic events from another client during the run.

1. **Fresh pending:** complete language/terms only. Inspect the explicitly
   provisional Ariadne notice without allowing collection. The synthetic probe
   returns false and adds no row. A former Matomo decision is not consulted.
2. **Reject:** choose **Keep off / revoke**, then invoke the probe and navigate.
   No new sends/rows. Restart this same disposable profile; it remains rejected.
3. **Accept:** Settings → Support → analytics notice → **Allow Ariadne analytics**.
   Confirm the saved status before probing. Invoke one probe and inspect the
   authorized Ariadne `/staff/analytics` totals/top pages. A new installation
   appears, labelled as an installation rather than a person.
4. **Accepted restart:** before closing, privately record the accepted identity
   from `<reviewRoot>\electron\ariadne-analytics.json`, network key `preprod`.
   Do not paste it into chat, screenshots, logs or shell history. Restart through
   the same watchdog/profile, probe again, and compare identities privately:
   unchanged. Daily active installations should not increase for this identity.
5. **Revoke during delivery:** use a local-only delay relay for this separate
   timing test, described below. Trigger a probe while accepted, then revoke
   before the pending request completes. Check the pending connection aborts,
   queued events do not resume, and later probes return false. An event already
   forwarded and committed may remain; revocation is not deletion.
6. **Revoked restart:** the store records `REJECTED` without `id`; capture the
   earlier synthetic identity privately before revoking so cleanup remains exact.
   Restart and confirm no send. The UI must not silently enable collection.
7. **Accept again:** click Allow and probe. The saved UUID must differ from the
   earlier accepted UUID. A second installation may now appear; this does not
   establish a second person. No old-generation or pre-consent events replay.
8. **Disabled configuration:** stop this review wallet, set its feature flag off,
   restart the same isolated profile. Allow is disabled/unavailable and the probe
   sends nothing. This is configuration disable, not identity deletion.

### Reproducible revocation timing

A developer-controlled relay must bind only `127.0.0.1:3189`, accept only the v1
event path, and forward exclusively to `127.0.0.1:3000`. It must not log bodies,
UUIDs or addresses, follow redirects, persist events or replay cancelled requests.
Hold a request for four seconds before forwarding and discard it if the client
disconnects. The five-second client timeout remains unchanged. The prepared helper is `.git/analytics-completion-review/delay-relay.cjs`;
start it yourself with `node .git/analytics-completion-review/delay-relay.cjs`.
It binds only loopback and forwards only to port 3000; running it is your action.

For this test only, use `http://127.0.0.1:3189/api/analytics/event` in the trusted
main-process configuration. Restart, then explicitly accept: changing recipient
URL intentionally requires fresh consent and a fresh identity. Click revoke
while the relay reports a held request, within four seconds. Repeat if the request
was forwarded before the click. Check held/forwarded/cancelled counters, not request
contents. Return to the direct port 3000 endpoint afterward; that also requires
fresh consent. Save each test identity privately before revoking or switching
recipient. This timing scenario is outstanding interactive validation; mocked
cancellation/race tests already pass.

For v2 attempts, the review fixture in Ariadne shows explicit start/terminal
semantics without transactions. In the wallet, opening and closing delegation/
registration before submitting should yield one cancelled attempt when accepted.
Do not create/fund a wallet or send a real transaction for this analytics review.
Automated mocked flows cover successful submission/QR completion and async races;
real backend and hardware success remain unperformed checks.

If an empty wallet cannot open a wizard, use this **synthetic** main-frame probe
instead of creating a wallet or funding a transaction. Explicitly accepted consent
is still required. Run once with `completed` and once with `cancelled`; the
owner generates both IDs, and the dashboard exposes only aggregate results.

```javascript
window.ariadneAttemptProbe = async (flow, terminal) => {
  const view = await window.ipcRenderer.invoke('ARIADNE_ANALYTICS_CONSENT_V1', { get: true });
  const attempt = Date.now() * 1000;
  const results = [];
  for (const stage of ['started', terminal]) {
    results.push(await window.ipcRenderer.invoke('ARIADNE_ANALYTICS_EVENT_V1', {
      type: 'funnel_step', action: flow, attempt, stage,
      ts: new Date().toISOString(), generation: view.generation,
      uses_legacy_wallet: false, uses_hardware_wallet: false,
    }));
  }
  return results;
};
await window.ariadneAttemptProbe('delegation_submit', 'completed');
await window.ariadneAttemptProbe('voting_registration_setup', 'cancelled');
```

These are fixture endpoints, not evidence of real wallet transaction success.

## Cleanup and evidence boundaries

Stop the review wallet/renderer/relay and Ariadne yourself. Keep the list of only
this profile's synthetic installation IDs in a private local file; never use a
date/network-wide delete. Follow Ariadne `docs/analytics-ingestion.md`'s stopped-
owner procedure: open its existing analytics DB once, bind each synthetic UUID
to the selective deletion query, verify its remaining count is zero, then close
the DB before restarting Ariadne. Preserve every other row, support LMDB, configs,
keys and backups. The dashboard demo cleanup command removes its own fixtures,
not these wallet-generated identities. Logical deletion is not secure erasure.

Only after selective cleanup is verified may the operator remove the exact
disposable profile they created; first resolve and check its full path remains
inside `DaedalusAriadneReview`. Never delete `%APPDATA%`, installed Daedalus data,
an Ariadne data root or a path derived from a real wallet. Retain only aggregate
test results and pass/fail identity comparisons in the review evidence.

Completed automated checks and outstanding gates are in the companion
[implementation SOP](ariadne-analytics.md). The temporary cross-repository harness
can be rerun immediately without either application: from Ariadne run
`npx.cmd tsx scripts/verify-daedalus-analytics.ts --daedalus-dir ../daedalus`.
It uses actual application handlers and disposable DuckDB with mocked in-process
delivery; it does not prove Windows Electron, real HTTP, native backends,
packaged HTTPS or interactive consent. Those remain separate acceptance gates.
