# Watchdog as Entry Point PRD

## Overview

This document describes the next architectural milestone in the Daedalus backend
process supervision story: making `cardano-watchdog` the process-tree root (PID 1
of the Daedalus process family), with Electron demoted to a pure display process
that communicates with the watchdog over anonymous stdio pipes.

This is the direct successor to the Watchdog Architecture milestone
(`.agent/plans/watchdog/watchdog-prd.md`), which moved process management out of
TypeScript and into Rust. That work left Electron as the _parent_ of the watchdog.
This milestone inverts that relationship.

---

## Why This Milestone Matters

### Architectural context

The Watchdog Architecture PRD framed this as part of a broader frontend refresh:
> "Without a clean separation between 'the UI' and 'the backend supervisor,' the two
> concerns remain entangled in ways that slow down every future change."

The watchdog milestone achieved that separation at the _code_ level. This milestone
achieves it at the _process_ level. When Electron is the parent it is still, by OS
definition, a process supervisor. Every crash-recovery path, every platform signal
quirk, every "what happens when Electron hangs" scenario falls on the UI layer to
handle. Inverting the tree makes those concerns the watchdog's problem — in Rust,
where they belong.

### Why now

The native package work (`sl/linux-packaging`) removes the auto-update mechanism
that was the last surviving reason for `cardano-launcher` to exist:

- **Auto-update is gone.** Package updates are delivered by apt/dnf/pacman/nix.
  The exit-code-20 restart loop, the `update-runner` shim, and the
  `daedalus-frontend` escape-hatch script all become dead code.
- **cardano-launcher's only remaining jobs** were (a) spawn Electron and restart it
  on exit-code-20, and (b) resolve binary paths from `launcher-config.yaml`. Both
  disappear with auto-update.
- **The process tree can finally be straightened.** With no updater, the correct
  shape is: one Rust binary starts everything; Electron is just a display process.

### Security improvement

The IPC between parent and child uses anonymous OS pipes — private file descriptors
that no other process can enumerate, connect to, or read. This is the most secure
possible local IPC mechanism. It is also the simplest: no Unix socket, no Named
Pipe, no TCP port, no access-control list. The OS enforces isolation by construction.

Contrast with the current design: Electron writes a JSON config file to disk, then
spawns the watchdog with that file path as an argument. Any process with filesystem
read access to the state directory can read the watchdog config, including binary
paths and wallet port assignments.

## Problem Statement

### Current process tree

```
bin/daedalus (shell script)
  └─ exec cardano-launcher (Haskell binary)
        └─ daedalus-frontend (shell script)
              └─ exec electron → Electron main process (Node.js)
                    └─ spawn cardano-watchdog (Rust)
                          ├─ cardano-node
                          └─ cardano-wallet
```

Five layers between the shell entry point and the wallet. Two of them
(`cardano-launcher`, `daedalus-frontend`) exist solely to support the now-removed
auto-update flow.

### Current IPC direction

Electron (parent) writes a `watchdog-config.json` to disk, spawns the watchdog,
reads events from the watchdog's stdout, and writes commands to its stdin. The
config file sits on the filesystem, readable by any local process.

### Consequences

- Electron is a process supervisor despite being a UI framework.
- `cardano-launcher` (a Haskell binary) is a build dependency with no remaining purpose.
- `WatchdogManager.ts` exists to spawn, monitor, and communicate with the watchdog —
  TypeScript code that is purely about process management, not display.
- `BackendLifecycle.ts` picks free TCP ports and builds argument lists for Rust
  binaries — again, not display logic.
- TLS certs for the wallet REST API are generated by `cardano-launcher` at launch,
  creating a dependency on that binary for a security-critical operation.
- The `launcher-config.yaml` format carries both binary-path fields (only for the
  launcher) and UI-config fields (only for Electron), in one file, causing confusion
  about what each field is for.

## Goals

- Make `cardano-watchdog` the direct child of `bin/daedalus`; it spawns everything else.
- Electron communicates with the watchdog exclusively via stdin/stdout anonymous pipes.
- Remove `cardano-launcher` from all platform bundles.
- Remove `daedalus-frontend` script, `update-runner` shim, and all auto-update code.
- Move TLS cert generation into the watchdog (Rust, using `rcgen`).
- Move port-picking into the watchdog.
- Move node/wallet argument assembly into the watchdog config (generated by Nix at
  build time, not assembled by TypeScript at runtime).
- Split config: `watchdog-config.json` (binary paths, process args) vs a slimmed
  `launcher-config.yaml` (UI display config only).
- Deliver all platform entrypoint changes: Linux `bin/daedalus`, macOS
  `darwin-launcher.go`, Windows NSIS installer.
- Electron crash policy: let the process tree die; user re-launches via OS.

---

## Non-Goals

- Removing Electron entirely (a future milestone).
- Changing any renderer component or MobX store behavior.
- Adding new IPC channels.
- Changing how `cardano-node` or `cardano-wallet` are invoked beyond the argument
  assembly moving from TypeScript to Nix config.
- Modifying the Mithril sync lifecycle (already in Rust).
- Adding watchdog restart-of-Electron logic (decided: die on crash).

## Locked Planning Decisions

- **IPC transport**: anonymous OS pipes via stdio (stdin/stdout of the Electron child
  process). No Unix socket, no Named Pipe, no TCP port.
- **Protocol**: identical newline-delimited JSON protocol as today. Direction is
  inverted: watchdog writes events to Electron's stdin; Electron writes commands to
  its stdout.
- **emit() abstraction**: a `OnceLock<UnboundedSender<String>>` in `protocol.rs`
  decouples all `emit()` call sites from the sink. A drain task in `main.rs` writes
  to either `tokio::io::stdout()` (standalone mode) or Electron's `ChildStdin`
  (parent mode). Zero call-site changes in `supervisor.rs` or `mithril.rs`.
- **Port-picking**: moves to Rust. If `wallet.api_port` is absent in config, the
  watchdog binds a `TcpListener` to port 0, reads the assigned port, closes the
  listener, and uses that port for the wallet.
- **TLS**: kept. Cert generation moves to Rust using the `rcgen` crate (pure Rust,
  no system OpenSSL). Generated into `$stateDir/tls/` before wallet is spawned.
  Cert paths passed to Electron as env vars (`TLS_CA_CERT`, `TLS_CLIENT_CERT`,
  `TLS_CLIENT_KEY`) so Electron can authenticate to the wallet API.
- **Electron crash policy**: broken write pipe → watchdog sends `Command::Stop` →
  node+wallet shut down cleanly → watchdog exits. No restart. User re-launches.
- **Config split**: `watchdog-config.json` (binary paths, process args, Mithril
  config, electron binary path) generated by Nix at build time. `launcher-config.yaml`
  retained but stripped of all binary-path and updater fields; it becomes Electron's
  UI-config file only (cluster, network name, state dirs, log prefix, URLs).
- **All platforms in scope**: Linux `bin/daedalus`, macOS `darwin-launcher.go`,
  Windows NSIS — all land in this branch.
- **Standalone mode preserved**: if `electron` section is absent from
  `watchdog-config.json`, watchdog emits events to its own stdout and reads commands
  from its own stdin (current behavior). Useful for CLI/diagnostics use.

### Functional Requirements

- [ ] `bin/daedalus` (Linux) execs `cardano-watchdog --config watchdog-config.json`
      directly; no `cardano-launcher` invocation.
- [ ] `darwin-launcher` (macOS) execs `cardano-watchdog --config watchdog-config.json`
      directly; no `cardano-launcher` invocation.
- [ ] NSIS installer (Windows) shortcut points to `cardano-watchdog.exe`; no
      `cardano-launcher.exe` in the installer.
- [ ] `watchdog-config.json` is generated by Nix at build time and contains: node
      binary path and full args, wallet binary path and full args (without port or TLS
      flags — those are added by the watchdog at runtime), Mithril config, and electron
      binary path and args. Runtime-variable fields (`pub_logs_dir`, `tls_dir`) are
      **not** baked into the JSON; they are passed as `--pub-logs-dir` and `--tls-dir`
      CLI flags from `bin/daedalus`.
- [ ] Watchdog generates TLS certs at startup using `rcgen` before spawning wallet or
      Electron. CA, server, and client certs written to `$stateDir/tls/`.
- [ ] Watchdog picks a free wallet port at startup (if `api_port` absent in config).
- [ ] Watchdog spawns Electron as a child process with `stdin: piped, stdout: piped,
      stderr: piped`. `tether_to_watchdog()` applied so Electron cannot outlive watchdog.
- [ ] All watchdog events are written to Electron's stdin (not watchdog's stdout).
- [ ] All watchdog commands are read from Electron's stdout (not watchdog's stdin).
- [ ] Watchdog monitors Electron's exit: clean exit → `Command::Stop`; broken write
      pipe → `Command::Stop`. Both paths shut down node+wallet cleanly.
- [ ] `ElectronStarted { pid }` and `ElectronExited { code, signal }` events are
      emitted (to Electron's stdin before it dies, or to watchdog stderr/log).
- [ ] `WatchdogManager.ts` reads events from `process.stdin` and writes commands to
      `process.stdout`. The `spawn()` call is removed entirely.
- [ ] `BackendLifecycle.ts` `start()` takes no binary-path or config-building arguments.
- [ ] TLS cert paths are available in Electron via env vars set by watchdog before spawning.
- [ ] `launcher-config.yaml` retains only UI-config fields; all binary-path and updater
      fields are removed.
- [ ] `cardano-launcher` binary is removed from all platform bundles (Linux deb/rpm/arch/
      nixos, macOS app bundle, Windows installer, nix self-extracting bundle if retained).
- [ ] `daedalus-frontend` shell script is removed from Linux libexec.
- [ ] `update-runner` shell script is removed from Linux libexec.
- [ ] `cardano-launcher.exe.manifest` is removed.

### Non-Functional Requirements

- All Rust changes compile and pass `cargo test` on Linux, macOS, and Windows targets.
- `yarn compile` passes with no new type errors.
- `treefmt` passes (rustfmt + prettier).
- `cardano-launcher` is no longer a Nix flake input or build dependency on any platform.
- The standalone watchdog mode (no `electron` config section) continues to work for

- No new IPC channels introduced in Electron.

## Technical Design

### Target Process Tree

```
bin/daedalus (shell)
  └─ exec cardano-watchdog --config watchdog-config.json
        ├─ [Electron's stdin ← events]  electron  [Electron's stdout → commands]
        ├─ cardano-node   (shutdown pipe fd 3 / stdin on Windows, unchanged)
        └─ cardano-wallet (stdio, unchanged)
```

### emit() Abstraction (protocol.rs)

Current `emit()` calls `std::io::stdout().lock()` and writes directly. Adding a
`OnceLock<UnboundedSender<String>>` lets `emit()` remain a synchronous call at every
site while the async drain task decides the actual sink:

```rust
static EVENT_TX: OnceLock<tokio::sync::mpsc::UnboundedSender<String>> = OnceLock::new();

pub fn init_event_sink(tx: tokio::sync::mpsc::UnboundedSender<String>) {
    EVENT_TX.set(tx).ok();
}

pub fn emit(event: &Event) {
    if let Ok(line) = serde_json::to_string(event) {
        if let Some(tx) = EVENT_TX.get() {
            let _ = tx.send(line);
        } else {
            println!("{line}");   // standalone fallback
        }
    }
}
```

No changes to the ~30 `emit()` call sites in `supervisor.rs` and `mithril.rs`.

### Electron Spawn Logic (main.rs)

After reading config and initializing the event sink, if `config.electron` is `Some`:

1. Generate TLS certs (`tls::generate_certs(stateDir)`)
2. Pick wallet port if `config.wallet.api_port` is `None`
3. Spawn Electron: `stdin: Stdio::piped(), stdout: Stdio::piped(), stderr: Stdio::piped()`
4. Apply `tether_to_watchdog()` to Electron child
5. Drain event channel → Electron's `ChildStdin`; broken write → `cmd_tx.send(Stop)`
6. Read commands from Electron's `ChildStdout` using existing `read_bounded_line` logic
7. Spawn task: `electron.wait().await` → `cmd_tx.send(Stop)`
8. Emit `ElectronStarted { pid }`

### TLS Cert Generation (watchdog/src/tls.rs)

New module using `rcgen`. Generates:
- `$stateDir/tls/server/ca.pem` — self-signed root CA (10-year)
- `$stateDir/tls/server/server.pem` + `server.key` — server cert signed by CA (1-year)
- `$stateDir/tls/client/client.pem` + `client.key` — client cert signed by CA (1-year)

Same file layout as cardano-launcher produced. Cert paths injected into Electron's
environment (`TLS_CA_CERT`, `TLS_CLIENT_CERT`, `TLS_CLIENT_KEY`).

### WatchdogManager.ts After Refactor

The `start(exePath, config)` method becomes `start()`:

```ts
start(): void {
  // No spawn(), no writeFileSync(), no config-building.
  // Events arrive on process.stdin; commands go to process.stdout.
  const rl = createInterface({ input: process.stdin, crlfDelay: Infinity });
  rl.on('line', (line) => { /* same handleEvent() as today */ });
  rl.on('close', () => { /* replaces proc.on('exit') */ });
}

sendCommand(cmd: object): void {
  process.stdout.write(JSON.stringify(cmd) + '\n');
  // was: this.proc.stdin.write(...)
}
```

`handleEvent()` is unchanged — all 130 lines of event dispatch stay as-is.
`stop()` sends the stop command to `process.stdout` and resolves when `process.stdin`
closes (watchdog closes our stdin after the backends shut down).

## Rollout / Migration / Rollback

- No feature flag. The change is structural; it ships as a complete replacement.
- Users on the previous nix-bundle self-extracting installer are migrated to native
  packages (`sl/linux-packaging`); the bundle does not need to support the new tree.
- Rollback: revert the branch. No data migration; state directory layout is unchanged.
  TLS certs are regenerated on each launch so stale certs from cardano-launcher are
  harmless.
- `cardano-launcher` remains in the Nix flake inputs until this branch lands; it is
  removed from `flake/lib/daedalus.nix` (which absorbs `nix/internal/common.nix`) as
  part of this work. The `cardano-shell` flake input is also removed at that point.

## Open Questions

None. All three open decisions were resolved prior to planning:
1. TLS: **keep** — cert generation moves to Rust (`rcgen`).
